1

建飞书表格 约 8 分钟

账目最终存在这里。手机上随时翻，也能自己做透视表和图表。

  1. 打开 feishu.cn，注册或登录（没有账号用手机号注册，免费）。
  2. 首页右上角「新建」→ 选「多维表格」→ 空白表格 → 命名 我的账本。
  3. 默认表格自带「文本」「单选」等列，全部删掉：点列标题 → 菜单里选「删除字段」。
  4. 按下面这张表建 5 列。建列：点表格最右侧的 + 或最后一列标题上的 +。
列名字段类型要点
金额数字小数位数设成 2
类型单选建好后进「编辑字段」，先加两个选项：支出、收入，一个字都不能差
备注多行文本保持默认即可
分类多行文本建议就用文本。用单选的话要把 10 个分类全建好，漏一个就写入失败
日期日期必须是日期类型。编辑字段里勾上「显示时间」，格式选 yyyy/MM/dd HH:mm

建好之后应该长这样

我的账本 · 多维表格
金额类型备注分类日期
25支出午饭餐饮2026/11/01 12:30
这三个错误会让后面卡住，现在避开 ① 列名多一个空格（金额 ）—— 后面自检会明确告诉你找不到列
② 日期列建成「文本」—— 查询筛选会失效
③ 「类型」建了单选却没加「支出 / 收入」两个选项 —— 写入直接报错
列名不想用中文？ 可以，但要在配置里告诉程序。比如你想叫 amount，就加一行 FEISHU_FIELD_AMOUNT=amount。先按中文建最简单。
2

抄表格的两个 ID 约 2 分钟

不用进任何后台，看浏览器地址栏就够了。

表格打开后，地址栏长这样（把中间两段抄下来）：

地址栏
https://abc123.feishu.cn/base/bascnCMIxxxxxxx?table=tblAbCdEf123&view=vewXyZ
第 3 个值： FEISHU_APP_TOKEN = /base/ 后面、? 前面的那一串
第 4 个值： FEISHU_TABLE_ID = table= 后面、& 前面的那一串，一般以 tbl 开头
如果地址里是 /wiki/ 而不是 /base/ 说明这张表建在知识库里，接口读不到。新建一个普通多维表格（不走知识库），或者把表移到「我的空间」下再打开。
3

建飞书应用，拿 App ID 和 Secret 约 8 分钟

这一步是让程序有「写你表格」的身份。

  1. 打开 open.feishu.cn，用同一个飞书账号登录，进入「开发者后台」。
  2. 点「创建企业自建应用」。名称填 记账机器人，描述随意 → 创建。
  3. 左侧「凭证与基础信息」：抄下 App ID（cli_ 开头）和 App Secret（点眼睛图标显示，cli_ 和 Secret 是两回事，别抄错）。
  4. 左侧「权限管理」→ 搜索框输入 bitable → 勾选「查看、评论、编辑和管理多维表格」。
  5. 左侧「添加应用能力」→ 找到「机器人」卡片 → 点 + 添加。
    这一步不能省 飞书官方规定：用应用身份（tenant_access_token）访问别人的表格，前提是应用已开启机器人能力。不开的话，下一步在表格里搜不到它。应用名带「机器人」三个字，也不等于开了机器人能力。
  6. 左侧「版本管理与发布」→ 「创建版本」→ 版本号填 1.0.0 → 保存并申请发布 → 提交。
    可用范围必须包含你自己 发版时如果弹「可用范围」，选全体成员或至少把你自己的账号加进去。可用范围里没有表格所有者，同样搜不到应用。
  7. 你是管理员，审核自己就能过：右上角进「管理后台」→ 应用审核 → 通过。
第 5 个值： FEISHU_APP_ID = 凭证与基础信息页的 App ID，cli_ 开头
第 6 个值： FEISHU_APP_SECRET = 同一页的 App Secret，点显示后复制
应用必须「发布」过一次 没发布的应用，下一步在表格里搜不到，接口也返回权限错误。发布后改权限的话，要重新创建版本再发布一次才生效。
4

把应用加进表格 约 2 分钟

整份指南里最容易翻车的一步。不是动作难，是入口不在你以为的地方。搜不到应用，按下面 4.2 逐条查，一定能解决。

先记住这句话，能省你半小时 表格右上角那个「分享」弹窗，是给人用的 —— 搜人、搜群、搜部门都行，但搜不到应用，输入应用名只会显示「未能找到相关结果」。
应用走的是另一条路：右上角「···」→「···更多」→「添加文档应用」。

4.1 找到真正的入口

多维表格 / 我的账本
加「人」用的弹窗 — 请输入姓名或邮箱，搜应用一无所获 ❌
右上角这个按钮，先点它
展开二级菜单 ← 真正的入口藏在这里
在这里搜「记账机器人」，才搜得到 ✅
  1. 打开你的「我的账本」多维表格（在飞书里，不是开发者后台）。
  2. 看页面右上角：除了蓝色的「分享」，右侧还有一个「···」或「···更多」按钮。
  3. 点它 → 下拉菜单里再点「···更多」（这里还有一层）。
  4. 选「添加文档应用」，会弹出一个专门的窗口，标题写着「添加文档应用」。
  5. 在这个窗口里输入 记账机器人 → 选中 → 权限选「可编辑」→ 点添加。
怎样算真的加成功了 加完回到「分享」面板，协作者列表里应该多出一个带「应用」标签的「记账机器人」。看到它才算成功，光点完按钮不算。

4.2 用了正确入口还是搜不到？按顺序查这 3 条

这三条是飞书官方写明的硬性前提，缺任何一条，应用都会从搜索框里消失：

可能性怎么确认怎么修
① 应用没开机器人能力
最常见
 开发者后台左侧「应用能力」下面，有没有「机器人」这一项？只有「添加应用能力」说明还没加。 「添加应用能力」→ 机器人卡片 → + 添加 → 然后必须重新创建版本并发布，改动才生效。
② 发布的可用范围不含你 「版本管理与发布」里，当前版本那行的「可用范围」是什么？ 改成「全体成员」，或手动把自己加进去。表格所有者不在可用范围里，搜索结果里就没有这个应用。
③ 没开通云文档 API 权限 「权限管理」里搜 bitable，那几项是不是还是「未开通」状态。 勾选「查看、评论、编辑和管理多维表格」→ 重新发版。应用一个云文档权限都没有时，搜索框直接不返回它。
改完任何一项，都要重新发一次版 飞书的规则是「应用能力」和「权限」的变更，只有在新版本发布后才生效。只保存不发布，等于没改。你截图里显示「当前修改均已发布」——如果之后又加了机器人能力，这句话就会变成「有未发布的修改」，记得再走一遍「创建版本 → 发布」。

4.3 表格开了「高级权限」的话

如果这张表右上角有「高级权限」入口且处于开启状态，加应用时权限必须选「可管理」，选「可编辑」照样写不进去。 不确定的话：先按「可编辑」加，第 7 步跑自检报 91403，再回来把它改成「可管理」。

4.4 兜底方案：从群组绕过去

万一「添加文档应用」窗口始终搜不出应用，用官方给的第二条路 —— 把应用拉进一个群，再把群加为协作者。群名一定搜得到，这条几乎不会失败：

  1. 飞书客户端新建一个群（只放自己一个人也行）。
  2. 群设置 → 群机器人 → 添加机器人 → 搜「记账机器人」添加。
    注意要选你的应用本身，不是「自定义机器人」——那是个 webhook，跟这里无关。
  3. 回到多维表格 → 右上角「分享」→ 搜这个群名 → 加为协作者 → 权限「可编辑」。

应用作为群成员，就自动继承了群的文档权限。

到这里，飞书的 4 个值齐了 App Token、Table ID、App ID、App Secret。先别急着填，等第 6 步一起填。

注册企业微信，建一个应用 约 10 分钟

它负责把你在微信里发的消息转给程序，再把结果回给你。

5.1 注册

  1. 打开 work.weixin.qq.com → 右上角「立即注册」。
  2. 填写：团队名称（写「个人账本」就行）、行业（选其他）、人员规模（1–50 人）、管理员姓名和手机号。
  3. 用微信扫码验证，完成注册。
不需要营业执照、不需要企业认证、不需要对公打款 未认证团队一样能用自建应用和消息回调，只是成员上限少。你自己用完全够。

5.2 拿企业 ID

  1. 用管理员微信扫码登录管理后台（也可以从注册完成页直接进）。
  2. 顶部「我的企业」→「企业信息」→ 拉到最下面「企业 ID」。
第 1 个值： WECOM_CORP_ID = 我的企业 → 企业信息 → 企业 ID，ww 开头的一串

5.3 建应用

  1. 顶部「应用管理」→「应用」页 → 找到「自建」区域 → 点「创建应用」。
  2. 应用名称填 记账，logo 随便传一张（或跳过），可见范围选「你自己」→ 创建。
  3. 点进这个应用，页面里找到「接收消息」区域 → 点「设置 API 接收」。

会弹出这样一个配置框（注意：现在还不能填 URL）：

企业微信 · 设置API接收
部署完云函数再回来填（先别点保存）
点右边「随机获取」，然后抄走
同样点「随机获取」，抄走这一长串
第 2 个值： WECOM_TOKEN = 「随机获取」生成的 Token（3–32 位字母数字）
第 3 个值： WECOM_AES_KEY = 「随机获取」生成的 EncodingAESKey，正好 43 位，少一个字符都不行
先别点「保存」 URL 还是空的，现在点保存一定失败。这两个值抄下来就够了，等第 8 步部署完云函数，拿到地址再回来填 URL 保存。

写进项目根目录的 .env 文件。.env 不进版本库，仓库里只有 .env.example 作模板：复制一份改名，或直接跑 node tools/setenv.js --paste 把上面这段整段粘进去，它会校验格式并自动备份旧文件。

它会自己校验格式、把旧文件备份成 .env.bak、连注释一起写整齐。格式不对会拦下来，不会写坏。

或者手动改（不想用命令的话）

  1. 打开 项目文件夹（就是放着 index.js、src 这些文件的那个目录）
  2. 找到名为 .env 的文件 → 右键 →「打开方式」→ 记事本。
    看不到这个文件？在资源管理器顶部「查看」里勾上「文件扩展名」。它是普通文件，不是隐藏文件。

  4. 把上面生成的内容粘进去 → Ctrl+S 保存。
别搞混：.env 和「云函数环境变量」是两回事 .env 只在你这台电脑上生效，第 7 步的本地自检读的就是它。
云函数上没有这个文件 —— 部署时（第 8 步）要在这 7 个值在腾讯云控制台的「函数配置 → 环境变量」里再填一遍。
所以这两个地方的值必须一模一样，填错一个就会出现「本地能记、微信里不行」。
这个页面里的内容只存在你自己的浏览器里 不会上传到任何地方。但生成的文件包含密钥，不要截图发群、不要提交到 GitHub（项目里已经有 .gitignore 挡住了）。

本地自检，别跳过 约 3 分钟

一条命令把 7 个凭证全测一遍，顺带查应用能力、权限、表结构。红了就修，别带着问题去部署。

在项目目录里执行：

cd suiyin node tools/check.js --write

它会依次检查这些，逐项给结论：

检查项会告诉你什么
1. 配置格式CorpID 是不是 ww 开头、AESKey 是不是 43 位、有没有多空格
2. 飞书应用认证App ID / Secret 对不对，能不能换到 token
3. 机器人能力应用开没开机器人能力 —— 这就是「表格里搜不到应用」的头号原因，提前告诉你
4. 表格访问权限第 4 步「添加文档应用」有没有加成功。报 91403 就是没加上
5. 列名与类型会把表里实际的列名列出来，列名不一致直接指出来
6. 单选选项「类型」里有没有「支出」「收入」
7. 真实写入写一条 0.01 元的测试记录再删掉（带 --write 才做）
8. 日期查询日期筛选能不能用，抽样打印一条真实记录

· 列「日期」类型不对 → 回第 1 步把日期列改成日期类型

node src/local-server.js 然后另开一个终端 node tools/sim.js "25 午饭"
8

部署到云函数 约 15 分钟

让程序跑在公网上，企业微信才找得到它。不需要买服务器。

8.1 打包

node tools/pack.js

生成 dist/suiyin.zip（约 29 KB，已自动排除 .env 和测试文件）。

8.2 注册腾讯云

打开 cloud.tencent.com，注册并完成实名认证（个人认证，用身份证 + 人脸，几分钟）。

8.3 新建函数

搜索进入「云函数 SCF」控制台 → 「函数服务」→ 「新建」→ 选「从头开始」，按下表填：

项目填什么
函数类型事件函数 —— 页面上第一个选择项，别选成「Web 函数」
函数名称suiyin
地域选离你近的，比如「广州」
运行环境Node.js 18 或更高（Nodejs16 及以下不行，没有 fetch）
提交方法本地上传 ZIP 包 → 选 dist/suiyin.zip
执行方法index.main（注意是点号，不是斜杠）
内存256 MB（免费额度内，别用 128 MB：冷启动时容易吃紧）
超时时间10 秒 —— 默认是 3 秒，必须改，否则「飞书记上了、微信没回信」
日志配置默认投递 —— 不选的话，出问题连日志都看不了（见下）
日志配置必须选「默认投递」，否则以后排查问题会卡住 新建函数页面底部有一个「日志配置」区域，两个选项：默认投递 / 自定义投递。

选「默认投递」，SCF 会自动帮你开通日志服务 CLS，把调用日志投到 SCF_logtopic_xxx 这个专用主题里，保留 7 天。 不配置的话，点「日志查询」只会看到「您的函数尚未进行日志配置，无法查看函数调用日志」， 这时候任何报错都查不出来，只能靠猜。

已经建好、当时漏配了？函数详情 →「函数配置」→ 编辑 → 找到「日志配置」→ 选「默认投递」→ 保存。 改完只对之后的调用生效，之前的不会补录 —— 所以配完要再去微信发一条消息，才会有新日志。
日志服务是独立计费产品，但 SCF 专用主题在免费额度内，个人记账这点量用不完。
超时时间默认 3 秒，这一项漏了会出现最迷惑的故障 企业微信要求 5 秒内回包。一笔账的处理是「写飞书 → 查本月合计 → 组织回包」，3 秒很容易不够。
函数被强制中断的瞬间，飞书那边已经写完了，可回包永远发不出去 —— 你会看到「账确实记上了，微信里却一条回信都没有」，然后企业微信开始重试，飞书里多出几条重复记录。

建完之后再去「函数配置」核对一次：超时时间 10 秒、内存 256 MB。
函数类型：一定选「事件函数」，不能选「Web 函数」 这是新建页面的第一个选择项，两个选项长得都挺合理，选错了后面全都白做。

Web 函数要求代码包里有一个可执行的 scf_bootstrap 文件，由它启动一个监听 9000 端口的 HTTP 服务。我们的 zip 里没有这个文件——代码是 exports.main(event, context) 的事件函数写法，选 Web 函数会在启动阶段就报错，函数压根跑不起来。

事件函数才是我们这套的路子：函数 URL 把 HTTP 请求转成 JSON 事件交给 index.main，函数返回 {statusCode, headers, body}，函数 URL 再把它原样映射成真实响应。企业微信要收到一段精确的 XML，这条链路才对得上。

如果已经建成 Web 函数了，删掉重建（30 秒的事），别去试着改代码适配——两条路的写法不一样。

8.4 配环境变量

函数创建好后，进「函数配置」→「编辑」→ 环境变量。一共要加 8 个，key 名照着下面抄（别手打），value 从 .env 里复制：

WECOM_CORP_ID WECOM_TOKEN WECOM_AES_KEY FEISHU_APP_ID FEISHU_APP_SECRET FEISHU_APP_TOKEN FEISHU_TABLE_ID APP_STORE=feishu
APP_STORE 必须是 feishu，不是这 7 个里的任何一个 它是第 8 个，也最容易忘。留空或写成 json，数据会写进云函数的临时目录 —— 函数一冷启动就全部消失，而你在微信里看到的回执一切正常，根本不会发现。
为什么不直接把 .env 打包进去 环境变量在控制台改，改完立即生效，不用重新上传代码；而且 zip 包万一外传也不会带出密钥。

8.5 开启函数 URL（关键一步）

不要去「触发管理 → 创建触发器」。API 网关产品已于 2025 年 6 月 30 日下线，那个弹窗里已经没有「API 网关触发器」了，剩下的定时触发、COS 触发都不是 HTTP 入口，选了也没用。

正确入口在函数详情页左侧导航栏的 「函数 URL」。它是函数的专属 HTTP(S) 端点，不经过网关、不用备案、地址永久不变——比原来的网关方案还少一个坑。

腾讯云 · 新建函数 URL
$LATEST（默认）
启用 —— 不勾外网访问不到
不启用
不勾（不用浏览器调接口）
开放 —— 千万别选「CAM 鉴权」
授权类型必须选「开放」 选「CAM 鉴权」的话，每个请求都要带腾讯云签名。企业微信服务器不会签，请求会被直接挡在门外——SCF 日志里连一条调用记录都不会有，现象和「URL 填错」完全一样，非常难查。

点确定后，页面给出一条地址，形如：

https://abc12345-xyz98765.ap-guangzhou.tencentscf.com

这条地址永久不变（绑在版本上，不是临时域名），复制下来，第 9 步要用。

好消息：不需要勾「集成响应」了 API 网关时代必须勾那一项，否则函数返回的 {statusCode, headers, body} 会被当 JSON 原样吐出去。
函数 URL 是原生解析这个结构的——只要返回值里有 statusCode，它就映射成真实的 HTTP 状态码、响应头和 body。我们的 index.js 本来就是这个格式，所以什么都不用额外配。

回填回调 URL，验收 约 3 分钟

企业微信会立刻发一个验证请求过来，通过就说明整条链路通了。

  1. 回到企业微信管理后台 → 应用管理 → 你的「记账」应用 → 「接收消息」→「设置 API 接收」。
  2. URL 填第 8 步拿到的那个地址（整条，带结尾的斜杠也没关系）。
  3. Token 和 EncodingAESKey 保持你之前抄的那两个值不动作。
  4. 点「保存」。
保存成功 = 企业微信 → 云函数 → 回包 整条链路都通了 想确认的话，去腾讯云 SCF 控制台「日志查询」，能看到 [wecom] URL 验证通过。
保存失败，按这个顺序查 ① 浏览器直接打开那条地址，看不到 missing echostr → 回 8.5，公网访问没启用或授权类型选错
② 提示「域名主体校验未通过」→ 见下方单独说明
③ 日志里有请求但返回 401 → Token 抄错了
④ 日志里没有任何请求 → URL 填错，或函数没部署成功
⑤ 报 解密失败：receiveid 不匹配 → CorpID 填错了
提示「域名主体校验未通过，需配置备案主体与当前企业主体相同或有关联关系的域名」 这是企业微信对已认证企业的限制：认证过的企业只能用「备案主体和企业主体一致」的域名，tencentscf.com 这种公共域名过不了。

两个出路：
· 未认证企业不受这条限制——可以配置非服务商的公共域名。你如果是新建的免费团队（未认证），通常不会遇到这个提示；真遇到了，先确认企业状态是不是「已认证」。
· 已经有认证企业、非用不可：去腾讯云函数「高级能力 → 自定义域名」绑定你自己已备案的域名，再把这个域名填进企业微信。

卡在哪步说明什么

三步全绿云函数侧没问题，问题在企业微信那边 —— 看下面
三步全绿但微信里还是没反应，先做一个判断 打开飞书多维表格，看刚才那条消息有没有变成一行记录。答案不同，原因完全不同：
飞书表格里说明和修法
没有新记录 消息根本没推过来。企业微信后台 → 应用 →「接收消息」→「设置 API 接收」→ 页面下方「选择需要接收的消息事件类型」里， 要勾上「消息事件」或「文本消息」。
只填 URL 不勾类型，URL 验证照样通过，但消息永远不会推 —— 这是最容易误判的一种。
有新记录 消息到了、账也记上了，只是回信没送回去。看同一条内容是不是重复了 2～4 行：
· 重复 → 企业微信在重试，说明函数没在 5 秒内回包，第一嫌疑是云函数超时时间太小（见下）
· 只有 1 行 → 回包发出去了但被丢弃，多半是 Content-Type 或响应结构被网关改写
「飞书有记录、微信没回信」的元凶：云函数超时时间还是默认 3 秒 腾讯云新建函数时，超时时间默认 3 秒。一笔账的处理顺序是：写飞书 → 再查一次本月合计 → 组织回包。 如果卡在 3 秒被强制中断，飞书那边已经写完了，回包却永远发不出去 —— 症状就是「账记上了，但微信里一点动静都没有」，而且企业微信会重试，飞书里于是多出几条重复记录。

修法：函数详情 →「函数配置」→ 编辑 → 超时时间改成 10 秒，内存建议提到 256 MB（128 MB 在冷启动时容易吃紧），保存即可，不用重新上传代码。
顺手压一下耗时（可选） 在云函数环境变量里加 APP_SHOW_TODAY_TOTAL=0，记账回执就不再查「今日/本月」，能少一次飞书往返， 回包时间大约减半。代价是回信里只有这一笔，看不到合计。想先求稳可以先关，稳了再打开。
