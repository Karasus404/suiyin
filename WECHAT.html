记账机器人 · 通道迁移

在微信里用它

现在这套程序跑在企业微信里。想换成微信不一定要重做——有三条路，成本差得很远。先看表，再看步骤。

一、三条路，先选一条

路径要做什么多久代价

③ 个人订阅号

先说结论 先花 5 分钟试 ①，不行立刻上 ②。②在微信里的体验和正式公众号完全一样，而且免费、免审核、不查备案。 只有当你打算长期稳定地给别人用时，③ 才值得。
不管你选哪条，企业微信那边都不用拆 代码现在支持两套凭证同时存在，靠签名自动识别消息从哪来。你可以一边用着企业微信，一边把微信通道接上，互不干扰。

二、换通道到底要改什么

企业微信和公众号是两套接口，但核心算法一模一样（都是 WXBizMsgCrypt 那一套 AES-256-CBC）。真正的差别只有三处：

对比项企业微信公众号
验签参数msg_signature安全模式 msg_signature；明文模式 signature
receiveidCorpID（ww 开头）AppID（wx 开头）
是否加密必须加密可选：明文 / 兼容 / 安全
消息 XML完全一样（ToUserName / FromUserName / Content）
5 秒回包限制一样
这部分我已经改完了 代码现在会自动判断一条请求属于哪个通道、是加密还是明文，然后按对应方式回包。 你要做的只是把公众号的 3 个凭证填进配置，一行代码都不用碰。

三、路径 ①：微信插件（5 分钟，先试这个）

企业微信自带一个功能叫「微信插件」——本质就是原来的微信企业号。关注之后，你的企业应用会出现在个人微信里。

步骤

  1. 企业微信管理后台 → 我的企业 → 微信插件。
  2. 页面上有个「邀请关注微信插件」的二维码，用个人微信扫，点关注。
  3. 回到这个页面，确认两处：
    • 取消勾选「成员使用微信插件时需要使用企业微信客户端」——勾着的话，点任何应用都会强制跳企业微信。
    • 确认「消息同步」是开着的。
  4. 手机企业微信 → 左上角「≡」→ 设置 → 新消息通知 → 取消勾选「仅在企业微信中接收消息」。
  5. 打开个人微信，在公众号列表或「通讯录 → 我的企业」里找到它，点进去 → 底部「工作台」→ 找你的「记账」应用。
怎么判断这条路能不能用 点进「记账」后，如果看到的是一个能打字的对话框，那就能用——直接发「25 午饭」，什么都不用改。
如果看到的是网页、或者只显示历史通知、或者提示"请在企业微信中打开"，就说明这条路走不通，别耗时间，直接去第四节。
为什么它可能不能用 微信插件主要是为「接收通知」和「打开 H5 应用」设计的。能不能跟自建应用对话，取决于应用类型和企业微信版本， 而且这个能力这几年在收紧。所以：5 分钟试一次，成了省一小时，不成也不亏。

四、路径 ②：微信测试号（推荐）

微信官方给开发者留的后门：扫码就有完整的公众号能力，不用注册、不用审核、不查域名备案。在微信里的样子就是个普通公众号。

测试号的两个关键特性，正好适合你 ① 不校验域名备案——腾讯云函数那个默认域名可以直接填；
② 它的接口配置只有 URL 和 Token，没有 AESKey 选项，也就是天然走明文模式，配置最简单。

2.1 拿测试号（2 分钟）

  1. 电脑上打开：https://mp.weixin.qq.com/debug/cgi-bin/sandbox?t=sandbox/login
  2. 手机微信扫码登录。
  3. 页面上直接给你 appID 和 appsecret，另外还有一个「测试号二维码」——这个二维码待会儿要扫，先别关页面。

2.2 先配凭证，再填 URL（顺序不能反）

测试号页面上「接口配置信息」点提交时，微信会立刻来验证你的服务器。所以必须先把凭证配好、函数能正确回应，再去填 URL。

  1. 腾讯云 → 云函数 → 你的函数 → 函数配置 → 编辑 → 环境变量，新增两个：
    WECHAT_APP_ID = wx 开头的那串 WECHAT_TOKEN = 你自己定，比如 jizhang2026
    只需要这两个。明文模式不需要 WECHAT_AES_KEY，留空即可。
  2. 保存。环境变量改动后函数会自动重启，不用重新上传代码包。
Token 要一致 这里填的 WECHAT_TOKEN 必须和待会儿在测试号页面填的 Token 一字不差，包括大小写。 不一致的表现是：保存 URL 时报「配置失败」，函数日志里写着 签名校验失败。

2.3 填 URL 并保存

  1. 回到测试号页面，找到「接口配置信息」→ 点「修改」。
  2. URL：填你的云函数地址，就是之前企业微信回调用的那个，形如
    https://xxxxx-xxxxx.ap-guangzhou.tencentscf.com
  3. Token：填刚才那个 jizhang2026（或你自定的值）。
  4. 点「提交」。微信立刻发一个 GET 请求来验证 —— 通过了会提示「配置成功」。
提交后没反应 / 提示失败，按这个顺序查 ① 函数日志里有没有那条 GET 请求？没有 → URL 填错，或函数 URL 的公网访问没开；
② 有请求但返回 401 签名校验失败 → Token 两边不一致；
③ 返回 200 但页面还提示失败 → 检查返回值是不是纯文本 echostr，不能带标签或多余空格。
本地可以先跑 ping.cmd 你的URL，第 2 步就是专门测这个的。

2.4 扫码关注，开始记账

  1. 在测试号页面找到「测试号二维码」，手机微信扫一下并关注。
  2. 打开微信，进这个公众号的对话框，发：25 午饭
  3. 收到「✅ 支出 ¥25.00 · 午饭（餐饮）」就说明通了。
测试号的三个使用须知 ① 只有扫过二维码的微信能用——你自己扫了就行，最多能加 100 个；
② 长期不登录测试号管理页，可能会被回收，偶尔去登录一次保活；
③ 它支持的接口比个人订阅号还多（有客服接口，将来想做每日推送也能做）。

五、路径 ③：个人订阅号（要长期给别人用时）

如果你想让家人朋友也能用，就得走正式公众号。这里有一个必须先说的硬门槛。

域名这一关绕不过去 公众号的服务器配置要求 URL 是 80 / 443 端口 + 域名，而且实践中未备案域名基本会被拦。 腾讯云函数那个默认域名能不能过，取决于微信当时的校验策略——可能能存进去，也可能被拒，而且有被限流的风险。

备案要 7～20 天、域名约 50 元/年。所以除非你确实要长期对外，否则别走这条。

流程

  1. 注册：mp.weixin.qq.com → 立即注册 → 订阅号 → 主体类型选「个人」（身份证 + 人脸识别）。
  2. 等审核，一般 1～7 天。
  3. 「设置与开发」→「基本配置」→ 记下 AppID。
  4. 「服务器配置」→ 修改配置：
    URL云函数地址，或你自己的备案域名
    Token自己定，3～32 位
    EncodingAESKey点「随机生成」，43 位
    消息加解密方式安全模式（推荐）；调试期可以先用「明文模式」
  5. 提交后，把 WECHAT_APP_ID / WECHAT_TOKEN / WECHAT_AES_KEY 三个都填进函数环境变量。
  6. 回到「服务器配置」页面，点「启用」。
保存成功 ≠ 已经启用 公众号的服务器配置保存之后，页面顶部还有一个「启用」按钮。不点它，消息一条都不会推过来， 但配置页面看起来一切正常。这是公众号开发里最高频的"配了半天没反应"。

企业微信没有这个按钮，所以从那边迁过来的人几乎都会踩一次。

个人订阅号做不到的事

  • 没有客服接口，不能主动给你推送（每日汇总、账单提醒这类做不了）——测试号反而可以；
  • 自定义菜单、网页授权等能力需要微信认证（个人主体无法认证）；
  • 每天只能群发 1 次。

但被动回复完全够用：你发一句，它回一句，正是记账要的形态。

六、配置（三条路共用的部分）

不管你走哪条路，凭证都是填进同一个地方。命令一条搞定：

.\setenv.cmd --channel=wechat

它会只问公众号的 3 项 + 飞书的 4 项，逐个粘进去即可。也可以手动改 .env：

# 公众号 / 测试号 WECHAT_APP_ID=wx1234567890abcdef WECHAT_TOKEN=jizhang2026 # 明文模式留空；安全模式填 43 位 WECHAT_AES_KEY= WECHAT_MODE=auto
变量什么时候要填
WECHAT_APP_ID必填。测试号管理页顶部的 appID；公众号「基本配置」里的 AppID
WECHAT_TOKEN必填。和后台填的 Token 一字不差
WECHAT_AES_KEY测试号 / 明文模式：留空。公众号安全模式：填 43 位
WECHAT_MODE一般写 auto，程序自己判断
云函数上也要填一遍 .env 只在你本机生效，云函数没有这个文件。上面这几个变量要在 云函数 → 函数配置 → 环境变量里再填一次，两边保持一致。
企业微信那几个变量不用删，留着就能同时用。
填完先自查格式
.\setenv.cmd --show
它会打印当前配置，并在最下面告诉你现在实际启用了哪几套通道（企业微信 / 公众号安全模式 / 公众号明文模式）。

七、不碰微信就能测的本地验证

填完凭证后，别急着去微信里试错。本地跑一遍，链路通不通当场就知道：

node src/local-server.js # 另开一个窗口： node tools/sim.js --wechat "25 午饭" # 公众号安全模式 node tools/sim.js --wechat --plain "8 地铁" # 公众号明文模式 node tools/sim.js "12 早餐" # 企业微信（原来的）

模拟器做的事和微信服务器一模一样：加密 → POST → 校验签名 → 解密回复。跑通了再上线。

实测输出（公众号明文模式）
→ 通道: 公众号 · 明文模式 → 发送: 8 地铁 HTTP 200 ← 机器人回复: ✅ 支出 ¥8.00 · 地铁（交通） 今日 ¥51.00 ｜ 本月 ¥51.00

上线之后想远程验证函数 URL 通不通，还是用那个探测工具。只配了公众号的话要加 --wechat，否则它会按企业微信凭证去试：

.\ping.cmd https://你的函数URL --wechat

八、排错速查

现象原因和修法
测试号提交 URL 提示「配置失败」 ① Token 两边不一致（最常见）；② 函数 URL 的公网访问没开；③ 返回的不是纯文本 echostr。先跑 ping.cmd 的第 2 步。
公众号保存成功，但微信里发消息没反应 没点「启用」。服务器配置页面顶部有启用按钮，不点不推送。企业微信没有这一步，从那边迁过来必踩。
提示「该公众号暂时无法提供服务」 函数 5 秒内没回包。把 APP_SHOW_TODAY_TOTAL=0（少查一次飞书）；顺便确认云函数超时时间不是默认的 3 秒。
回复内容对，但微信里显示乱码 回包 Content-Type 要是 application/xml; charset=utf-8。代码里已经写死，出现乱码多半是网关改写。
测试号发消息，日志里有 receiveid 不匹配 WECHAT_APP_ID 抄错了，或者是别的公众号的 AppID。测试号的 appID 在管理页顶部。
公众号提示「redirect_uri 域名与后台配置不一致」 这条和记账无关——是本项目以外的网页授权问题。记账只用消息推送，不需要配网页授权域名。
企业微信那边突然不能用了 不会。两套凭证并存，各自独立。除非你把 WECOM_* 删了或者 Token 改错。
测试号隔了几个月不能用 长期不登录被回收了。重新扫码申请一个，换 WECHAT_APP_ID 和 WECHAT_TOKEN 即可。
一句话选路 只想自己在微信里用 → 测试号（第四节），30 分钟，免费，不查备案。
想让家人也用 → 先各自扫码加测试号白名单（能用）；不够再上正式订阅号 + 备案域名。
不想折腾任何注册 → 先试微信插件（第三节），5 分钟见分晓。
